### 4.1 止盈三档状态机方案

**状态定义:**
- state=0:未止盈(初始)
- state=1:已卖一半(第一档触发后)
- state=2:已卖 3/4(第二档触发后)
- state=3:本轮结束(第三档触发后)

**各档触发条件:**
- 第一档(state 0→1):`(current - avg_cost) / avg_cost >= 0.25` → 卖 remaining/2
- 第二档(state 1→2):`current >= trigger2_price * 1.10`(trigger2_price = 第一档卖出价)→ 卖 remaining/2
- 第三档(state 2→3):先满足前置 `highest_price >= avg_cost * 1.30`(历史最高价曾达+30%,不要求当前仍≥30%),然后 `drawdown = (highest - current) / highest >= 0.10` → 卖 remaining 全部

**第三档防误触发:** 必须 state==2(已经卖过两档)且 highest_price 已记录(意味着确实涨到过高位),才计算回撤。避免"快涨快回"在 state 0/1 时误触发清仓。

**重置机制:** state==3 时,下一次 `recorder.add_purchase()` 自动调 `profit_taker.reset()`,开启新一轮。不在 check() 里自动重置(避免 check 有副作用)。

**highest_price 更新:** 每次 check() 时,如果 current > highest_price 则更新并写入 state.json(这是 check 的唯一副作用,追踪必需)。第三档前置条件判的是 `(highest_price - avg_cost) / avg_cost >= 0.30`(历史曾达),而非当前浮盈仍≥30%——峰值后回落,当前可能已低于 30%,但只要曾到过就满足前置。

### 4.2 卖出份额计算(以剩余持仓为基数)

- `remaining = total_shares - cumulative_sold`
- `cumulative_sold` 从 `state.json` 的 `sell_records` 列表求和(不从 xlsx 读,因为 xlsx 只记买入)
- 第一档:sell = remaining / 2 = total / 2(首次 remaining==total)
- 第二档:sell = remaining / 2 = (total - 第一档卖的) / 2
- 第三档:sell = remaining(全部清余)

**为什么不能直接改 xlsx 持仓?** xlsx 是"买入流水账",记录的是每次买了多少;卖出是另一个维度的事件。如果在 xlsx 里扣减持仓,会破坏"累计投入"的计算(投入不变,只是份额换了形态)。正确做法:sell_records 独立记录在 state.json,需要"当前持仓"时用 total - sold 算。

### 4.3 止盈接主菜单

main.py 菜单增加:
```
6. 判止盈
```
调用流程:获取当前价(get_price_now 或手动输入)→ profit_taker.check(price) → 打印结果(action/sell_shares/message)→ 如果 trigger==True,提示用户"是否记录本次卖出?"→ 确认后调 record_sell()。

### 4.4 滚存真滚入下期

**落点:** xlsx 新增"累计滚存"列(recorder.add_purchase 增加 rollover 参数)。

**逻辑:** main.py 执行定投时:
1. 读上期记录的"累计滚存"值 → `last_rollover`
2. `available = config.DCA_AMOUNT + last_rollover`
3. `result = calculate_shares(available, price)`
4. 记账时把 `result['remainder']` 写入本期"累计滚存"列

**动态手续费:** `fee = max(cost * FEE_RATE, FEE_MIN)`,FEE_RATE=0.00025,FEE_MIN=5.0 写入 config.py。

### 4.5 浮亏 20% 预警哨点(方案 A·⑤纪律)

**在 main.py 的 option_view_portfolio() 中:** 算出 pnl_pct 后,如果 `pnl_pct <= -0.20`,打印:
```
⚠️ 浮亏已超过 20%!请核对三件事:
  1. 这笔钱还是闲钱吗?(性质变了→可以停;没变→继续)
  2. 后续现金流还在吗?(断了→自然停;没断→继续)
  3. 纪律还在吗?(反复想"这次跳过"=事实上停扣)
  结论:不卖。浮亏不是卖出理由,只是提醒你别犯恐慌错。
```

这是"能力"——方案 B 的巡检会把它包成自动推送。

### 4.6 自动化巡检方案(方案 B·纯函数 + Cron 提示词)

**纯函数设计: `inspector.py` → `check_all() -> dict`**

输入:无(内部读 portfolio.xlsx + 获取实时价格 + 读 state.json)
输出:
```python
{
    "price": float,           # 当前价
    "pnl_pct": float,         # 浮盈亏比
    "profit_action": str,     # 止盈判断结论
    "profit_trigger": bool,   # 是否触发止盈
    "pe_pct": float,          # PE 分位
    "pe_alert": str,          # PE 结论(偏高/低估/正常)
    "warning_20": bool,       # 浮亏≥20%?
    "summary": str            # 一段话总结(可直接推微信)
}
```

**五个检查点覆盖:**
- B-① 准备:返回 "ok"(不需检查)
- B-② 建仓:已有 Day7 Cron,巡检跳过
- B-③ 持有 PE:调 get_pe_data(),>70% 返回"偏高仅提醒",<30% 返回"低估可加回"
- B-④ 止盈:调 profit_taker.check(price),返回 trigger + action + sell_shares
- B-⑤ 纪律:调 analyze(),pnl_pct≤-20% 返回"核对三件事"

**关键约束:** 纯函数,无 input(),无副作用(不改 xlsx/state),可被 Cron/Skill/main 任意调用。

**Cron 提示词(每周一 9:00):**

> 调用 dca-tools Skill 执行周巡检。运行 inspector.check_all() 获取五个检查点结论。把 summary 字段推送到微信。如果有止盈触发或浮亏预警,额外加粗提醒。不替我下单,只给结论。如果全部正常,推"本周无异常,继续持有"。

### 止盈三档标尺(成本 1.000,持仓 1000 份)

| 再涨到第二档 | 1.000 | 1000 | 1.375(第一档卖价1.25×1.10) | 第二档 | 250(剩余500的一半) | 250 |

**第二档价格推导:** 第一档在 1.250 卖出,trigger2_price=1.250;再涨 10% = 1.250×1.10 = 1.375。
