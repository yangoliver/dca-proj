## 第二部分：Day 1 的核心理念

### Day 1 的本质是什么？

不是"安装一堆软件"，也不是"交一份作业"。

而是**学会和 QClaw 协作 + 学会用 GitHub 提交工作**——这两件事是 AI Native 工作方式的地基。

传统学习路径是"先学会再动手"。但 AI 时代可以反过来——先动手，遇到问题去问 QClaw，在解决问题的过程中学会工具。

**QClaw 是 Day 1 最重要的工具——它是你学会其他所有工具的途径。**
**GitHub 是 Day 1 最重要的协作习惯——它是你交付所有工作的标准通道。**

### AI 团队今天要"入职"谁？

| 工具 | Day 1 要做什么 | 最简单验证方法 |
|------|----------------|----------------|
| QClaw | 确认它能理解项目、能给出行动清单 | 发任务书 → 让它复述 → 问P0装什么 |
| Qoder CN | 下载安装 → 新建文件 → 写代码运行 | 新建 .py → print("hello") → 运行 |
| akshare | 安装 → 拉一条行情数据 | 获取中证500指数实时点位 |
| WorkBuddy | 安装 → 确认能响应基本指令 | 发一条测试指令确认 |
| GitHub | 注册 → fork 仓库 → 提交 Day 1 报告(PR) | PR 出现在 yangoliver/dca-proj |

## 第三部分：三种可能的执行路径（参考）

下面提供三种不同的执行路径。选哪种取决于你的习惯和风格。你也可以混合使用，或者完全走自己的路。

### 路径 A：先探索后行动（适合喜欢全局视角的同学）

**上午**
1. 打开 QClaw，发项目任务书，问："能帮我总结一下这个项目要做什么吗？"
2. 问 QClaw："P0 阶段我需要准备哪些东西？列个清单给我"
3. 问 QClaw："Qoder CN 和 WorkBuddy 怎么装？"
4. 问 QClaw："akshare 是什么？怎么验证能用？"

→ 上午结束前：手上有 QClaw 给的一份完整行动清单

**下午**
5. 按清单顺序安装：Qoder CN → WorkBuddy → akshare
6. 逐一验证：Qoder CN 能跑代码，akshare 能拉数据
7. 问 QClaw："我该选哪只中证500 ETF？怎么判断？"
8. 选定 ETF，记录理由

**优势：** 每一步都知道"为什么做这个"

### 路径 B：边做边问（适合喜欢动手试错的同学）

**上午**
1. 直接打开 QClaw，说："我要开始理财定投实习计划了，请给我指导"
2. 按 QClaw 的每一步指导立刻执行
3. 安装 Qoder CN，遇到问题立刻截图发给 QClaw
4. 安装 akshare，直接跑 QClaw 给的验证命令

**下午**
5. 让 QClaw 解释 ETF 费率对比怎么做
6. 根据 QClaw 的指导选 ETF，记录理由

**优势：** 行动快，适合不喜欢看大量文字的同学

### 路径 C：先搞定硬件再问 QClaw（适合动手能力强、已有基础的同学）

**上午**
1. 自己先完成 Qoder CN、WorkBuddy、akshare 的安装（如果你已经熟悉）
2. 安装完成后告诉 QClaw："工具准备好了，接下来做什么？"
3. 让 QClaw 给剩余任务排序
4. 按 QClaw 的优先级执行

**下午**
5. 问 QClaw ETF 费率的对比框架
6. 选定 ETF

**优势：** 节省探索时间，直接进入执行

> 无论选哪条路径，GitHub 作业提交流程（第五部分）都是必须的。

## 第五部分：GitHub 作业提交流程（必须）

Day 1 的作业不通过微信发文件，而是**通过 GitHub PR 提交**。这是真实工程协作的标准方式，从 Day 1 开始养成。

### 步骤 1：注册 GitHub 账户

1. 打开 https://github.com/signup
2. 填写用户名（建议用真名拼音，如 `yangzhixing`）、邮箱、密码
3. 验证邮箱，完成注册

### 步骤 2：Fork 本仓库

1. 打开 https://github.com/yangoliver/dca-proj
2. 点击右上角 **Fork** 按钮
3. 确认后，你的账户下会出现 `你的用户名/dca-proj`

> Fork = 复制一份仓库到你自己的账户，你拥有完整的写入权限。

### 步骤 3：Clone 到本地

```bash
git clone https://github.com/你的用户名/dca-proj.git
cd dca-proj
```

### 步骤 4：配置 Git（首次使用）

```bash
git config user.name "你的用户名"
git config user.email "你的邮箱"
```

### 步骤 5：写报告

1. 打开 `Day1/report/` 目录
2. 复制 `Day1/report/报告模板.md`，改名为 `Day1/report/你的名字_Day1报告.md`
3. 按模板填写（参考第六部分）

### 步骤 6：提交并推送

```bash
git add -A
git commit -m "day1: 完成Day1作业报告"
git push origin main
```

> 如果遇到 push 被拒（main 受保护），先开分支再 push：
> ```bash
> git checkout -b day1-report
> git push origin day1-report
> ```

### 步骤 7：提交 PR

1. 打开你 Fork 的仓库页面 `https://github.com/你的用户名/dca-proj`
2. GitHub 会提示 "Compare & pull request"，点击它
3. 标题填 `Day 1 报告 — 你的名字`
4. 说明里写：完成了哪些工具验证、ETF 选择理由、遇到的关键问题
5. 目标仓库选 `yangoliver/dca-proj`，目标分支 `main`
6. 点击 **Create pull request**

提交后，把 PR 链接发给 Oliver。Oliver 审阅通过后合并，你的作业正式进入项目仓库。

## 第八部分：常见问题 FAQ

**Q：QClaw 给的答案不对怎么办？**
先检查自己的问题是否够具体。AI 对模糊问题的回答也会模糊。试着拆小——"akshare 报错，错误信息是 XXX" 比 "装不上" 更有用。

**Q：QClaw 给的答案看不懂？**
直接说"我不太理解，能用更简单的方式解释吗？"好提问者会要求对方用自己能理解的方式回答。

**Q：能用别的工具代替 Qoder CN 吗？**
可以，但建议先按项目推荐的来，因为后续工具链是搭配设计的。如果坚持要换，找 QClaw 或 Oliver 讨论后再决定。

**Q：akshare 拉不出数据？**
常见原因：网络问题 / 依赖库没装 / 接口变动。先把错误信息发给 QClaw。还不行→截图给 Oliver。

**Q：WorkBuddy 装不上？**
问 QClaw 安装步骤。如果依然不行，用 Qoder CN 临时顶替编程任务。

**Q：GitHub 注册要填真实信息吗？**
用户名用真名拼音即可，邮箱用你常用的。不需要真实姓名，但建议 Oliver 能认出是你。

**Q：Fork 和 Clone 有什么区别？**
Fork 是在 GitHub 网站上复制仓库到你账户；Clone 是把仓库下载到你的电脑。先 Fork 再 Clone，你才能 push。

**Q：PR 提交后多久合并？**
Oliver 会在看到后审阅。PR 链接发给他即可，不用催。

**Q：Day 1 完不成怎么办？**
Day 1 的核心是和 QClaw 建立协作关系 + 掌握 GitHub 提交。部分目标延后到 Day 2 不影响整体进度，尽快追上即可。

**Q：我的做法和指南不一样，可以吗？**
可以。本指南是参考不是章程。不同的方法达成相同的结果就是成功。报告如实写你做了什么即可。
