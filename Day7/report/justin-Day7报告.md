## 一、对 Skill 的理解

### 1.1 什么是 QClaw Skill？

你的回答：

Skill 是一本「工具使用说明书」——告诉 AI 有哪些函数、各自干什么、参数和返回值是什么。AI 读了它就知道该调哪个函数、怎么调。

### 1.2 为什么要把 tools/ 变成 Skill？

你的回答：

tools/ 能用，但每次得自己开终端敲命令，AI 帮不上忙因为它不知道这些工具存在。变成 Skill 后入口从终端变成对话，一句话 AI 就能帮我跑。

### 1.3 变成 Skill 前后有什么不同？

| 场景 | 之前（手动操作） | 之后（AI 辅助） |
|------|----------------|----------------|
| 查持仓 | 打开终端 → python main.py → 选 2 → 看输出 | "帮我看看持仓" |
| 算份额 | 打开终端 → python calculator.py 3.95 → 看结果 | "3.95 元能买多少？" |
| 查估值 | 打开终端 → python portfolio.py → 找 PE 数据 | "现在 PE 分位多少？" |
| 止盈检查 | 打开终端 → python profit_taker.py → 看判断结果 | "帮我检查下止盈" |

## 四、对"AI + 定投"的理解

### 4.1 为什么说"定投是最适合 AI 管理的投资策略"？

你的回答：

定投的规则极其固定：到时间就买、不择时、金额固定。这意味着所有决策都可以被程序化——查价格、算份额、记流水、判断止盈，没有主观判断环节。AI 最擅长执行确定性规则，而定投恰好不需要"灵感"，只需要纪律。

### 4.2 你目前的状态和 AI 的分工

| 你做的 | AI 做的 |
|-------|--------|
| 决定投不投、下不下单 | 查价格、算份额、推送提醒 |
| 在中信 APP 手动买入 | 记录买入、更新持仓 |
| 确认止盈是否执行 | 监控浮盈、判断止盈条件 |
| 定规则（金额、周期、止盈线） | 按规则自动执行全流程 |

### 4.3 你认为这套系统最大的风险是什么？

你的回答：

过度依赖 AI 导致自己不动脑。如果哪天工具挂了或者数据源变了，我可能连手动算份额都生疏了。另外 AI 推送太方便也可能让人变成"无脑下单机器"，忘了去理解背后的逻辑。所以报告、复盘这些环节不能省。

### 4.4 算一笔账：你的工具值多少钱？

> 假设每次定投人工操作成本（不含交易费）：
> - 查行情价格：10 分钟（打开软件 → 搜索 → 记录）
> - 算份额：5 分钟（手动计算 → 检查比例）
> - 看持仓状态：5 分钟（打开 Excel → 累加 → 计算）
> - 每次合计：20 分钟
> - 20 次定投合计：400 分钟 ≈ **6.7 小时**
> - 写这些工具你花了多长时间？约 4 小时（Day3~Day7 累计，含调试）
>
> **工具投资回报率**：6.7h / 4h = **1.68**
>
> 你觉得值吗？为什么？

你的回答：

值。首先 1.68 倍回报只是时间账，实际上工具还能避免算错、忘记录、漏止盈这些隐性成本。而且写工具的过程本身就是学习——我因此真正理解了弹性股数法、PE 分位、复利滚存的计算逻辑，这不是 6.7 小时能换来的。

## 六、问题与解决（用 QClaw）

> 至少记录 2 个问题。

### 问题 1

- 问题描述：portfolio.xlsx 用 openpyxl 打开报 BadZipFile: File is not a zip file
- 怎么问 QClaw："portfolio.xlsx 打不开，报错 BadZipFile，怎么排查？"
- 怎么解决的：QClaw 用 xxd 查看文件头发现是 FF FE（UTF-16 BOM），判断文件被文本模式写入损坏。用 raw[2::2] 提取低位字节恢复了 PK 头，再从 git 历史确认原始文件就是损坏状态，最终重建了 xlsx 并补录了买入记录。

### 问题 2

- 问题描述：QoderWork 的 Write 工具无法写入 D:\ws\dca-proj（不在 workspace 内）
- 怎么问 QClaw：直接让它创建 skills/dca-tools/SKILL.md 时报了路径错误
- 怎么解决的：改用 Bash 的 cat heredoc 方式写入文件，绕过了 workspace 路径限制。
