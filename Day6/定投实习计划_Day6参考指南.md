## 二、止盈是什么？

### 2.1 任务书里的止盈规则（原文）

> **触发条件**：单轮浮盈 ≥ **+25%**
>
> **操作**：
> - 触发止盈 → 先卖 **1/2 持仓**
> - 若价格继续上涨，距离上次卖出点再涨 **10%** → 卖剩余的 **1/2**
> - **不清仓**：留底仓防踏空
> - **不停 DCA**：继续按计划定投
>
> **止盈后资金管理**：
> - 止盈资金转货币基金或债券基金（保持流动性）
> - 继续执行定投扣款（不中断）
> - 等 PE 近 5 年分位回落至 30% 以下，再分批把止盈资金加回

### 2.2 止盈的本质

**不是"逃顶"**，而是提前写好规则，机械执行。

- ❌ 错误理解：看到涨了很多，想"是不是该卖了"
- ✅ 正确理解：写好规则"涨到 25% 就卖一半"，到了就执行，不问为什么

### 2.3 止盈为什么不停 DCA？

**问题**：止盈后还继续定投吗？

**答案**：继续。止盈和定投是两件事：

| | 止盈 | 定投 |
|--|------|------|
| 是什么 | 卖出部分盈利筹码 | 按计划继续买入 |
| 触发条件 | 单轮浮盈 ≥ 25% | 时间到了 |
| 资金流向 | 转出场外 | 继续按计划买 |

**为什么不止盈后停止定投？**

1. 如果停止定投等跌回来，**你实际上在择时**（判断"会跌"）
2. 没有人知道止盈后会不会继续涨，停止定投可能错过后面的涨幅
3. 定投的纪律是"到了时间就买"，止盈卖出的钱不影响下期买入

## 三、止盈的轮次逻辑

### 3.1 什么是"轮"？

止盈是**按轮次**计算的，不是账户整体浮盈。

```
第1轮：持仓建立后，浮盈达到 25% → 触发止盈，卖 1/2
第2轮：如果价格继续涨，距离上次卖出点再涨 10% → 卖剩余的 1/2
第3轮：新的一轮开始...
```

### 3.2 止盈状态机

```
状态：未止盈
    ↓ 浮盈 ≥ 25%
状态：已卖 1/2（底仓 1/2）
    ↓ 价格继续涨 10%
状态：已卖 3/4（底仓 1/4）
    ↓ 价格继续涨 10%
状态：已卖 7/8（底仓 1/8）
    ...（永不空仓）
```

### 3.3 关键规则

1. **不清仓**：最多卖到剩 1/8 底仓
2. **不择时**：触发就卖，不等更高
3. **不止 DCA**：继续按计划定投
4. **估值参考**：PE 分位 > 70% 时提醒关注止盈（但触发止盈的是收益率，不是分位）

## 九、Git 协作与 Pull Request（重要）

### 9.1 为什么必须用 Pull Request？

**问题**：为什么不直接给 yangoliver/dca-proj 提交代码？

**答案**：因为你没有直接 push 到主仓库的权限，而且 Pull Request 有更重要的作用。

#### 直接 push 到主仓库的问题

```bash
# 你不能这样做（没有权限）
git push origin master  # ❌ 报错：permission denied
```

即使你有权限，直接 push 也有问题：
- 代码直接进入主分支，没有 review
- 如果代码有问题，影响整个项目
- 没有记录"谁提交的、为什么提交"

#### Pull Request 的设计目的

```
你的仓库（fork）                    主仓库（yangoliver/dca-proj）

your-name/dca-proj  ──PR──→  yangoliver/dca-proj
    ↑                          ↑
你在自己的仓库写代码           Oliver 在这里 review
                              没有你的权限，不能直接改
```

**Pull Request 不是权限限制，而是协作流程**：

| 没有 PR 的问题 | PR 解决了什么 |
|--------------|--------------|
| 代码直接进主仓库 | 代码先进 PR，需要 review |
| 不知道这段代码是谁改的 | PR 里有作者、理由、讨论记录 |
| 代码有问题直接污染主线 | PR 可以讨论、修改、甚至拒绝 |
| 多个人的代码混在一起 | 每个人自己的 PR，清清楚楚 |
| 不知道该不该合并 | Oliver 决定是否接受 |

#### 实际协作流程

```bash
# 1. 你 fork 了 yangoliver/dca-proj（已经有了）
#    你的仓库：https://github.com/你的名字/dca-proj

# 2. 你在自己的仓库里创建新分支写代码
git checkout -b day6-profit-taker
git add Day6/
git commit -m "feat(Day6): 止盈工具"

# 3. 把分支推到你的 GitHub 仓库
git push origin day6-profit-taker

# 4. 在 GitHub 上创建 Pull Request
#    从 your-name/day6-profit-taker → yangoliver/master

# 5. Oliver 在 GitHub 上 review 代码
#    - 如果有问题：在 PR 里评论讨论
#    - 如果没问题：Merge PR
```

#### PR 是对话，不是提交按钮

**PR 最重要的不是"提交代码"，而是"发起讨论"**：

- 代码写完后，创建 PR 意味着"我准备好了，请检查"
- Oliver 可以在 PR 里提问、提建议、甚至要求重写
- 你在 PR 里回复、解释、修改代码
- 最终 Merge 表示"这段代码经过确认，可以进入主线"

**好的 PR 包含**（在 PR 描述里写）：
